## Executed checks and attention coverage

Both logs record `uv sync --frozen --extra cuda --extra dev`, formatting, Ruff,
strict mypy, CPU/GPU pytest, both dense-workspace modes and reference
capture/repeat comparison. Formatting, lint and typing pass. Each pytest
invocation collects 632 cases: CPU selects and passes 617 while deselecting 15;
GPU selects and passes all 15 while deselecting 617. Neither report contains
failures, errors or skips. The CPU selection includes all 25 attention cases.

Both GPU JUnit reports explicitly record these passing cases from
[the CUDA attention suite](../../tests/gpu/test_attention_cuda.py):

- `test_paged_attention_boundaries_on_t4`: lengths 1/15/16/17/49/2048,
  noncontiguous queries, shuffled physical pages and eight-query-heads-per-KV-head
  mapping, including a separate 33-token head-mapping fixture.
- `test_paged_attention_large_scores_on_t4`: large positive/negative scores in
  both page orders and query scales 1 and 1,000.

The tests compare CUDA outputs against independent FP64 CPU attention at the
existing `atol=rtol=2e-3`. They require finite FP16 output, exact agreement with
the autocast-enabled call, unchanged pool contents/table/length/accounting,
exclusion of poisoned unused slots, and zero final ownership after release.
The pool storage pointer remains unchanged. Per-case attention error maxima
are not retained, so the evidence establishes passing tolerance assertions,
not exact numerical equality with the reference.

All other required GPU cases pass, including pinned paged prefill, dense
layer/greedy parity, both KV storage/ownership tests and reference verification.
Each dense tolerance envelope has 2,260 zero-error records, and each HF repeat
comparison has 39 zero-error tensors. Those records describe the dense decoder
and HF repeatability, respectively; they do not measure paged-attention error.

## Remaining gates and source boundary

Both dense-workspace modes pass nine runs with 27 samples each and zero
allocation retries/OOMs. The maximum dense increment is 1,128.05 MiB, also when
holding an unused 8,192 MiB reservation. This remains a one-sequence dense
probe; `capacity_validated=false` is correct. It does not validate paged/batched
workspace, 32-active service capacity or performance.

The current working tree differs from the tested revision in `attention.py`,
`decoder.py`, `kv_cache.py` and the decoder/allocator unit tests. In particular,
the later attention iterator and staged per-layer writes support batched
decode; they are absent from the archived implementation. P5.2 completion
therefore applies to the recorded standalone primitive. The newer integration
still requires T4 evidence.

P5.3 integrated decoder parity, P5.4 no-full-history-gather instrumentation,
P5.5-P5.7 integrated fragmentation/parity/workspace and safe page reuse remain
open. Worker lifecycle and HTTP/SSE are later gates. The current project gate
remains Phase 5; this review closes P5.2 only.
