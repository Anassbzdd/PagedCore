pool, 1,536 MiB margin and 32-active configuration remain provisional pending

## Findings and remaining work

1. **Collector required-test gap remains open.** The `required` set in
   [validate_t4.sh](../../scripts/validate_t4.sh) omits both pool/allocator test
   names. During review, its required-test guard accepted an in-memory copy of
   `gpu-tests.xml` with both cases removed. Both executed and passed in the
   original archive, so this gap does not invalidate this run. A future code
   change should require both names and add regression coverage for either
   missing case. Until then, inspect their actual execution in each GPU report.
2. **The newer P4.3 code needs its own T4 run.** The current working versions of
   `src/pagedcore/kv_cache.py`, `tests/unit/test_kv_cache.py` and
   `tests/gpu/test_kv_pool_cuda.py` differ from the archived hashes. The archive
   uses `create(request_id)` and predates reservation-aware admission, capacity
   snapshots and the added accounting assertions. Its 498 CPU passes do not
   replace the separate 502-test CPU result for P4.3 or validate P4.3 on CUDA.
3. **Phase 4 remains open.** P4.4 failure safety, P4.5 full boundary coverage and
   P4.6 independent property-model tests remain required. Small-pool reuse and
   stream rejection do not establish rollback, every terminal cleanup path,
   poisoned fragmented attention, batching or service memory safety.
